# ZCode 会话分析

根据用户给出的会话标题或关键词，在本机 ZCode 数据目录中定位目标会话，导出其内容并完成分析。整个流程只读取 ZCode 数据；不要修改 `db.sqlite` 或原会话。

## 输入与范围

- 优先使用用户提供的完整会话标题进行精确匹配。
- 用户只给关键词、标题已被截断或精确匹配为空时，使用模糊匹配。
- 同名或相近标题可能对应多个会话。此时展示候选项的标题、会话 ID、更新时间和工作目录，要求用户确认；不要猜测目标。
- 如用户直接给出 `sess_` 开头的会话 ID（`sess_<uuid>`）或合法裸 UUID，可跳过标题查询。
- 默认仅导出用户与助手消息（工具调用只保留名称一行）。只有当分析目标涉及命令、工具调用、浏览器操作、报错或执行结果时，才添加 `--include-tools`；需要思考过程时添加 `--include-reasoning`。

## 定位会话

技能目录记为 `<skill-dir>`。在 PowerShell 中运行：

```powershell
python "<skill-dir>\scripts\find_zcode_sessions.py" "用户提供的完整标题"
```

返回 JSON 只有一条时，读取其 `id`。返回空数组时，改用：

```powershell
python "<skill-dir>\scripts\find_zcode_sessions.py" "关键词" --contains
```

也可加 `--all` 列出全部会话（按更新时间倒序）。输出中不要展示数据库路径。对有多个匹配的情况，先让用户选择，或让用户补充大致更新时间；不要读取候选会话内容。

## 导出会话

将导出文件写入当前工作区的 `work/`，除非用户明确要求保留到其他位置：

```powershell
python "<skill-dir>\scripts\export_zcode_session.py" "<session-id>" --no-tools --output ".\work\zcode-session-<session-id>.md"
```

会话 ID 接受 `sess_<uuid>` 或裸 `<uuid>`。若需工具记录，省略 `--no-tools`（或显式传 `--include-tools`）。导出成功后检查命令输出中的 `entries` 大于零，并读取 Markdown。用户仅要求导出时，报告导出文件路径和条目数即可，不额外展开会话分析。若出现以下错误，按原因处理：

- `未找到会话 <id>`：确认会话 ID，检查 `~/.zcode/cli/db/db.sqlite` 是否仍保留该会话。
- 标题无匹配：提示用户使用更短的关键词、原始标题或更新时间。
- 多个匹配：停止在确认环节，不擅自选择。
- 导出内容为空：说明会话记录可能已被清理，或消息均为系统注入内容。

## 数据源说明

- 会话元数据（标题、工作目录、时间）来自 `~/.zcode/cli/db/db.sqlite` 的 `session` 表。
- 消息正文来自同库的 `message` 表（`role` 为 user/assistant）与 `part` 表（`type` 为 text/tool/reasoning/file）。
- user 消息中由系统注入的 `<system-reminder>` 块与带 `synthetic` 标志的 harness 注入消息（todo 提醒、上下文注入等）会被自动剔除；剔除后无正文的系统消息不会导出。
- `--no-tools`（默认）时工具调用仅输出一行 `> 调用工具: 名称列表`；`--include-tools` 时导出工具的输入与输出原文；`--include-reasoning` 时附上助手思考过程。
- 图片附件以 `（图片附件 mime）` 占位说明代替二进制数据。

## 归档到 Obsidian

用户要求把会话“存到 Obsidian / 归档到笔记”时，按本机中央 Vault 的既有口径落盘（Windows 为 `D:\GitHub\Obsidian_jerion\Vault`）。两条硬性规则：**必须落在 `ZCode 会话文档` 子目录**，**文件名必须带日期前缀**。

### 落盘位置：`<对应目录>/ZCode 会话文档/`

- `<对应目录>` 由会话主题决定，而不是由工作目录机械决定：项目类会话放 `Projects/<项目名>/`，运维类会话放 `服务器运维/<产品名>/`，其余按 Vault 现有分类就近归入。
- 该 `ZCode 会话文档` 子目录**不存在时必须先创建**，再把文档放进去。不要图省事把文件直接丢在项目/产品目录下——同级的 `Codex 会话文档/`、`DSH 会话文档/` 是姊妹目录，属于其它工具导出的会话，不要混放。
- 同一目录下的 ZCode 会话文档集中在该子目录内，便于整体查阅。

### 文件命名：`YYYY-MM-DD <主题>.md`

- 日期取**会话开始日**（`db.sqlite` 中该会话的 `time_created`）。会话跨天时，开始日更能反映工作实际发生的时点；若用户另有指定再改。
- 主题写清这段会话做了什么，可带项目/产品名前缀，例如 `2026-09-18 itdb-审计日志时间筛选与清空功能及v1.2.1发布.md`。
- 不要把 `ZCode 会话导出` 当作文件名，也不必附加会话 ID——ID 已写在文档元数据里。

### 执行细节

- 直接把 `--output` 指到最终路径，不必先导出再搬；路径含空格与中文时用引号包裹。
- 归档前按 Vault 规范做凭据脱敏：口令、token、密钥、私钥不得入库，命中处替换为 `********（已脱敏）`；内网地址与账号名属排障上下文，可保留。
- 落盘后回报完整路径、条目数与文件规模；内容较长时不要在对话里回贴正文，用户需要时自行在 Obsidian 查阅。

### 提交到 GitHub：自动提交，推送前必须确认

Vault 本身是 Git 仓库（Windows 位于 `D:\GitHub\Obsidian_jerion\Vault`，远程 `origin`，分支 `main`），会话文档落盘后按以下口径收尾：

1. **落盘后自动提交**，不必再问一次——这一步已获长期授权，属于本归档流程的固定收尾动作。
2. **只提交本次落盘的文档**：对每个文件单独 `git add "<路径>"`。禁止 `git add .` / `git add -A`——Vault 里随时可能有用户自己的在途改动（目录重命名、删除、其它笔记），一旦被裹进本次提交就污染了历史。
3. 提交信息沿用 Vault 既有风格（Conventional Commits，简体中文）：`docs: 新增 <项目> 会话文档（主题）`。一次提交里有多个文档时，在信息里并列写清涉及的项目。
4. 命令统一带 `-C` 指定目录，避免依赖当前工作目录：`git -C "<Vault 路径>" add "<文件>"`。注意仓库根其实是 Vault 的**上级**目录（Windows 为 `D:\GitHub\Obsidian_jerion`，Vault 是其中的 `Vault/` 子目录），所以 `git status` / `git log` 显示的路径可能带 `Vault/` 前缀；只要固定用 `-C "<Vault 路径>"` 并按 Vault 相对路径书写，两种显示都能对上。
5. **推送前必须单独征求确认**：提交完成后停下来问用户是否推送，得到明确答复前不要执行 `git push`。用户说“推一下”“同步到 GitHub”之类才推。
6. 回报时给出提交哈希、提交信息、本次涉及的文件；用户选择暂不推送时，说明提交已落在本地、待其决定。

## 分析与答复

阅读导出的会话后，回答用户实际提出的问题。默认用简体中文，并包含：

1. 目标会话：标题、会话 ID、最后更新时间。
2. 结论：直接回答用户的问题。
3. 证据：按时间说明相关用户诉求、关键回复、命令结果或状态变化。
4. 风险或不确定性：仅在确实存在时说明。

避免把完整会话原文、工具输出、绝对路径、密钥、令牌或个人信息直接贴回对话。需要引用时只给支撑结论的最小片段，并对敏感值脱敏。用户明确要求完整导出时，先提醒其中可能含有敏感信息，再按其指定的位置输出。

## 示例

### 按标题分析

用户说：“分析标题为‘itdb重构项目硬件数据三模块拆分优化’的 ZCode 会话，解释三个模块是怎么拆分的。”

先精确查询标题；唯一匹配后用 `--no-tools` 导出。由于问题涉及命令或文件改动时，再重新导出包含工具记录的版本，并基于会话证据解释结论。

### 直接按会话 ID 分析

用户说：“分析这个 ZCode 会话：`sess_5afe72b4-cea2-49fd-9fbc-bb5babc788dc`，重点说明最终修改了什么。”

校验会话 ID 格式后直接导出，跳过标题查询；读取会话内容并按用户关注点给出结论和证据。

### 直接导出会话 ID

用户说：“导出会话 ID `sess_5afe72b4-cea2-49fd-9fbc-bb5babc788dc`。”

校验后用 `--no-tools` 导出为 Markdown，报告导出路径与条目数，不额外分析内容。

### 导出会话并归档到 Obsidian

用户说：“把标题为‘itdb重构项目硬件数据三模块拆分优化’的 ZCode 会话导出到 Obsidian。”

按标题定位后，依会话主题判定归属目录（如 `Projects/itdb-new/ZCode 会话文档/`），目录不存在先创建；脱敏后以 `YYYY-MM-DD <主题>.md` 落盘，随后只添加该文件并提交到本地，最后询问用户是否推送到 GitHub——推送必须等用户明确答复。

### 导出包含工具记录的会话

用户说：“导出会话 ID `sess_5afe72b4-cea2-49fd-9fbc-bb5babc788dc`，包含工具调用和终端输出。”

校验后导出时使用 `--include-tools`；提醒导出文件可能含路径、命令输出或敏感信息，并报告导出路径与条目数。
